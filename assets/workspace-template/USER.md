# USER.md - 用户画像示例

> 这是一个**匿名化案例模板**，用于指导 onboarding 结束后如何整理用户画像。
> 不要把示例里的身份、地点、账号或平台细节当成当前用户事实。
> 当前工作区的真实运行配置应以仓库根目录 `config.yaml` 为准。

## 用途

- 给 Agent 一个“该记录什么、不该记录什么”的参考样式
- 在 onboarding 完成后，沉淀一份**人类可读**的用户画像摘要
- 作为 `config.yaml` 的补充说明，而不是替代品

## 隐私规则

- 只记录对协作有帮助的信息
- 默认使用概括描述，不写真实证件信息、手机号、邮箱、家庭住址、密钥、token
- 如果必须记录外部平台或知识库，只写“类型 + 用途 + 抽象位置”，不要写敏感 ID
- 用户明确说“不要记”的内容，不写入此文件

## 推荐写法

### 1. 用户是谁

- **称呼：** 示例用户
- **身份概述：** 内容创作者 / 研究型从业者 / 小团队负责人
- **工作重心：** 围绕 1-2 个长期主题持续产出内容
- **所在地或内容 base：** 可选，只在确实影响内容或协作时记录

### 2. 用户在做什么

- **主要项目或账号：**
  - 账号 A：示例方向 A
  - 账号 B：示例方向 B
- **典型任务：** 选题、转写、整理资料、写稿、归档、复盘

### 3. 用户希望我怎么协作

- **希望我扮演的角色：** 内容搭档 / 运营助理 / 写作教练 / 资料管理员
- **喜欢的风格：** 简洁、主动、给选项、少追问
- **协作禁忌：** 不催促、不替用户做最终决定、不写营销腔

### 4. 知识库与资料习惯

- **默认存储方式：** 本地 Markdown / Obsidian / Notion / 飞书
- **资料组织偏好：** 按项目、按账号、按内容类型分类
- **是否依赖云端 API：** 是 / 否

### 5. 需要长期记住的事

- 用户更在意持续协作体验，而不是一次性答案
- 涉及敏感发布、删除、外部分享时要先确认
- 有些偏好会放在 `config.yaml`，这里仅保留摘要

## Onboarding 完成后如何更新

当用户完成 onboarding 后，将本文件改写为当前用户的真实摘要版本：

1. 从 `config.yaml` 提取 `user`、`assistant`、`accounts`、`storage` 的关键信息
2. 只保留对后续协作真正有用的摘要
3. 删除示例措辞，替换成当前用户的实际情况
4. 继续遵守上面的隐私规则

---

知人方能善助，但用户画像不是档案表。写得越克制，越能长期使用。
